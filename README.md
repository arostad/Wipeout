# Wipeout

<img src="icon/AppIcon.iconset/icon_256x256@2x.png" width="180" align="left" alt="Wipeout">

<br><br>

macOS GUI for wiping a USB stick, SD card, or external NVMe back to a single full-size partition — including drives written by Rufus, Ventoy, dd, or any Linux tool that leaves partitions macOS refuses to touch. Replaces the diskpart-on-Windows workflow.

<br clear="all">

## Build

```bash
cd WipeoutRepo
INSTALL=1 bash build.sh
open ~/Applications/Wipeout.app
```

### Versioning

`VERSION` at the top of `build.sh` is the single source. It generates `Version.swift`,
stamps `CFBundleShortVersionString` and `CFBundleVersion`, and feeds the About panel.

| Change | Bump |
| --- | --- |
| Small change or fix | patch +1 (0.1.10 to 0.1.11) |
| New feature | minor +1, patch resets to 10 (0.1.14 to 0.2.10) |

`Version.swift` is regenerated on every build — never edit it.

| Variable | Effect |
| --- | --- |
| `INSTALL=1` | Also copies the bundle to `~/Applications` |
| `UNIVERSAL=1` | Builds an arm64 + x86_64 fat binary |
| `SIGN_ID="Name"` | Signs with a named identity instead of ad-hoc |

Requires Xcode Command Line Tools (`xcode-select --install`). Build takes 20–40 s.

## Layout

```
WipeoutRepo/
  build.sh                     compiles sources, assembles the .app, builds the icon
  Disk.swift                   device model + diskutil-backed scanner
  Version.swift                generated by build.sh; not tracked by hand
  FormatRunner.swift           script generation, privileged execution, log tailing
  UI.swift                     SwiftUI app entry point and main view
  icon/
    AppIcon.iconset/           10 PNGs; iconutil turns these into AppIcon.icns
    wipeout-icon.svg           1024 master (full-bleed)
    wipeout-icon-small.svg     simplified master used for the 16/32/64 slots
  resources/
    Shell.efi                  UEFI Shell 2.2 payload, bundled into the app
    Shell.efi.README.txt       provenance, checksum, license
  build/                       generated; deleted and recreated on every run
```

## What a run does

1. `diskutil unmountDisk force`
2. `diskutil eraseDisk free NONE <scheme>` — collapses the disk to a bare map
3. `diskutil zeroDisk force` — only when Deep wipe is checked
4. `diskutil partitionDisk <disk> 1 <scheme> <fs> <label> R`

All four go through diskarbitrationd, so no Full Disk Access grant is needed. One
administrator prompt per run, via `osascript`. Output streams to a temp log that the app
tails into the console pane.

Filesystems: ExFAT and MS-DOS FAT32 are pinned to MBR; JHFS+ and APFS to GPT. Volume
labels are sanitized automatically (11 chars, uppercase, for the FAT family).

## UEFI shell option

Picking "UEFI shell" formats FAT32 and stages:

```
EFI/BOOT/BOOTX64.EFI     the shell binary, where firmware looks on removable media
Update/                  empty, for BIOS update payloads
```

Boot the server from the stick, then at the shell prompt:

```
fs0:
cd \Update
dir
```

If `fs0:` is not the stick, run `map -r` and try `fs1:`, `fs2:`, and so on. Some firmware
requires disabling Secure Boot first, since this shell is not Microsoft-signed.

### Scheme

The UEFI option exposes an MBR/GPT radio choice; nothing else does.

| Scheme | When |
| --- | --- |
| MBR (default) | One FAT32 partition, nothing wasted. Firmware boots removable FAT media regardless of partition table. |
| GPT | Fallback for firmware that only enumerates ESP-typed partitions. `diskutil` adds a 200 MB EFI System partition and the shell lands on the data volume. |

CSM is irrelevant either way — `\EFI\BOOT\BOOTX64.EFI` on removable media is the UEFI
spec's own boot path, so this works on pure-UEFI machines with CSM disabled.

The payload comes from `resources/Shell.efi` at build time, or
`~/Library/Application Support/Wipeout/Shell.efi` at run time. The option is disabled
with an inline message if neither exists.

Staging runs in the app process, not in the privileged script. macOS gates writes to
removable volumes behind TCC, and only a foreground app can raise the one-click prompt —
a root child process just gets `Operation not permitted`. On the first UEFI-shell run
macOS asks to allow access; approve it once. If it was denied, the console says so and an
"Open privacy settings" button appears (Privacy & Security > Files and Folders >
Wipeout > Removable Volumes). Re-running after approving only re-stages the files.

## Safety

The whole disk backing `/` is detected via `APFSPhysicalStores` and blocked in both the
UI and the runner. Internal disks are hidden behind a checkbox. Dry run prints the exact
command sequence without touching the device.

## Notes

- macOS 26 restyles legacy `.icns` icons. If the Dock tile renders wrong, the fix is a
  real `.icon` built in Icon Composer, not another `.icns`.
- Stale Dock icon after a rebuild: `killall Dock`.
- Ad-hoc signing changes the code identity on every build. Use `SIGN_ID` with a
  self-signed Code Signing certificate for a stable one.
